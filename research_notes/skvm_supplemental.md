## 已核验的方法、证据与资源

SkVM 先测量模型与 harness 的能力，再执行能力适配、依赖绑定和并行机会提取。Compensation 降低能力要求，Substitution 更换实现路径。运行时根据执行记录触发重编译及回滚，或将稳定代码模板提升为无需模型生成的函数；失败时回退。

论文从技能语料归纳出 26 种能力原语，在 118 个任务、八种模型、三种 harness 上评估，每个任务生成五个输入实例。报告负迁移任务比例由 15% 降至 4.5%；某一组合 token 节省接近 40%；并行提速最高 3.2×；PDF 提取的代码固化提速 19–50×。演示中的天气预报任务始终未通过固化门。这些是不同实验的指标，不能合并成通用加速倍数。

实验执行主机为 Mac Mini M4/16GB，不等于八种大模型都在本机运行。devstral-small/Qwen3-30B 的目标画像测量分别耗时 7.3/31.1 分钟、花费 $0.033/$0.079；这是论文时期的 profiling 数字，不包含完整编译、优化和评测费用。编译仍调用 LLM，能力覆盖、不确定性和成本摊销均需考虑。[论文第 3–7 节](https://arxiv.org/html/2604.03088v3)

## 分析与局限

我们的判断：它的关键价值是生成“针对目标的可执行技能工件”，而不是假设一份 Markdown 技能天然适用于所有模型。应拆开验证四个问题：能力适配是否提高正确率；依赖预装是否只是消除了安装失败；并行调度是否降低延迟；重复工作能否改用普通程序完成。综合分数不能单独解释每个机制。

模板多次匹配只证明结构重复，不能证明任意输入下参数抽取都保留原意。应补测未见边界输入、输出格式变化、依赖漂移和错误固化比例。运行时异常容易发现，静默语义错误却未必触发回退。并发也需要识别共享状态，不能仅靠输出文本之间没有显式依赖来判断。这些是建议验证的问题，不是本次发现的实现漏洞。

不要将大规模技能语料数量当成实际执行任务数。论文引言中的平均提升“15.3%”，在分母和计算方式未明确前，不应改写成“15.3 个百分点”。无技能、原始技能、Skill-Creator 三种基线回答的问题不同，报告中应分别保留。

## 官方代码与版本审查

SJTU-IPADS 官方仓库公开且采用 MIT 许可证，提供 profiling、AOT 编译、JIT 优化和基准工具，并回链论文。当前代码已超出四月 v3 版本：五月新增默认进程内 pi 优化驱动及 Claude Code 适配器。数据子模块 README 列出 108 个技能、216 个任务，与论文任务数量不同。只有目标模型及适配器完全匹配时，才能复用预计算画像，省去再次 profiling。合成优化默认只有两个训练任务、一个留出任务，适合冒烟检查，不足以支持强统计结论。[官方仓库](https://github.com/SJTU-IPADS/SkVM)

当前使用文档支持 vLLM/Ollama 等本地 OpenAI-compatible 端点；区分只执行的 run 与带评分的 bench，可分别评测原始、AOT 和 JIT 条件。重要陷阱：real 模式若省略 --test-tasks，会将训练任务也用作测试任务；存在测试集时，收敛判断使用测试分数。因此，还需一个完全不参与选择的最终测试集。部分适配器因上游未保存用量而报告 $0，不能将其解释为真实零成本。[使用文档](https://github.com/SJTU-IPADS/SkVM/blob/main/docs/usage.md)

## 可行的无付费复现方案

以下仅为建议的有限实验，尚未完成，也不等同于论文完整复现。

### A. 不调用模型的确定性机制验证

构造小型离线技能集：处理 CSV 批次、转换本地 JSON、从人工生成的测试文件提取已知文本。提供明确的能力画像和编译工件，以避免 LLM 调用。检查版本选择、依赖检查幂等性、DAG 输出绑定、资源受限调度、连续结构匹配后的固化、结构变化时拒绝固化，以及注入错误后的回退。加入异常参数，以独立确定性检查器核对结果。

必须注明：手工编译工件或测试替身只能验证运行时机制，不能验证自动理解技能的能力。

### B. 条件具备后的本地模型小试验

若有合适硬件和已安装模型，使用一个本地编译模型及一个目标模型，两者可以相同，先用 bare-agent 适配器。禁用付费服务路由，排除依赖外部 API 的任务。选择与实际机器匹配的小任务，在相同种子、步数预算、隔离工作目录下比较无技能、原始技能、AOT、JIT。分别记录画像、编译、优化和任务执行的 token。

“无 API 费用”不代表没有电费和算力消耗。下载大模型权重、安装软件或改变系统设置前，仍需相应授权。

### C. 评测设计与停止条件

采用训练、验证、最终测试三份划分。只用训练/验证选择技能版本，选定后冻结，再运行最终测试。分别评测完整依赖与缺失依赖，单独测并行及编译收益；固化函数还应与直接手写函数比较。

优先记录任务正确性，其次是延迟分布、生成 token、编译成本、错误固化和回滚次数。出现不安全文件访问、意外联网、错误输出或预算耗尽时停止。报告失败和负迁移，不能仅展示成功案例。

### D. 成本与复现边界

摊销必须包含准备和优化：盈亏平衡调用次数 = 一次性画像、编译、优化成本 ÷ 每次调用的正向节省。如果每次节省为零或负数，就不存在盈亏平衡点。没有实际报价和已批准预算时，先报告本地实测秒数与 token，不虚构美元收益。

固定论文版本、源码提交、数据子模块提交、模型文件及量化方式、提示词和技能版本。不能悄悄将当前仓库便利默认值及扩展数据集替代论文设置。一种模型的小试验无法验证跨模型可移植性或论文最大收益。

## 与核心合集的联系

SkVM 为 Trace2Skill/WikiSkill 生成或演化的技能提供面向具体目标的适配。EvoC2F 关注具有效应约束的工具计划编译和宏技能验证；SkVM 关注技能可移植性、能力匹配和运行时专门化。DSec 提供隔离执行资源，SkVM 决定技能如何表示和调度。这些是架构比较，不是原文提供的同场基准对比结果。
