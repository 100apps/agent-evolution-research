# 提示优化、文本反馈与多智能体设计：原论文核查

核查日期：2026-10-08。范围为 5 项独立论文工作与 1 篇官方工程案例。TextGrad 的 arXiv 预印本与 Nature 正式发表是同一工作，不应重复计数。本文区分论文实测、研究者解释、我们建议的缩小实验；本次没有调用付费模型、执行第三方仓库代码或运行小模型实验。

## 共同概念：究竟在优化什么

- ProTeGi：优化某个任务的离散提示文字。
- TextGrad：在计算图中传播语言反馈，优化提示、答案、代码或其他文本化变量。
- FedTextGrad：把本地提示优化与跨客户端的提示聚合连接起来。
- SPRIG：优化跨任务共享的系统提示；其搜索代理还需训练奖励模型。
- MASS：交替优化代理提示和系统拓扑。
- Tax AI：用专家修正和生产追踪形成评测，再推动有边界的工程修改。

前三项的“文本梯度”不是对模型权重求导，也不意味着具有真实梯度的链式法则、下降保证或收敛定理。变量更新是模型根据语言批评生成新文本。SPRIG 的奖励模型训练则确实包含数值参数优化，不能把整篇工作归为“完全无需训练”。这些工作回答的层级不同，分数不宜横向排出统一排行榜。

## 1. ProTeGi / Automatic Prompt Optimization with “Gradient Descent” and Beam Search

### 来源与版本

- [arXiv v2 全文](https://arxiv.org/pdf/2305.03495v2)，2023-10-19，12 页；v1 为 2023-05-04。正式发表于 EMNLP 2023。
- [官方代码与数据](https://github.com/microsoft/LMOps/tree/main/prompt_optimization)。论文 v2 使用 ProTeGi 名称，摘要页部分文字仍称 APO。
- 阅读覆盖：§2 算法、§3 全部实验、附录提示模板、定性失败例和方差实验。下列页码按 PDF 页计。

### 核心方法与实测锚点

算法把一批错例交给 LLM，生成对当前提示的批评，再改写提示；释义扩增候选，beam search 保留多条路线，bandit 分配评测预算。§3.2（p.5）：主实验为 gpt-3.5-turbo，4 个分类任务，每任务 150 条测试样本、3 次试验，指标为二分类 F1。表1（p.6）中 Jailbreak 的 beam / greedy / 不迭代为 0.85 / 0.82 / 0.80；Liar 为 0.67 / 0.63 / 0.63。表2（p.7），每提示 50 次查询时 Jailbreak 的 UCB / uniform 为 0.85 / 0.77。主要参照包括 MC/APE 式释义搜索、短语编辑 RL、AutoGPT。图4提示多任务约第3步后收益停止或回落。[原文](https://arxiv.org/pdf/2305.03495v2)

### 分析：成立的结论与不能外推的结论

最有价值的对照是同预算搜索组件消融：语言反馈负责提出方向，beam 与 bandit 负责避免过早押注；它不是“批评一句就必然变好”。摘要的最高 31% 是特定实验中的最大改善描述，不能写成所有任务的平均提升，也不能直接解释成 31 个百分点。

主文写测试分数对最终 beam 做 maxpooling（§3.2）。独立复现应核查具体选择代码是否利用测试集择优，严格使用验证集选唯一提示，再一次性报告锁定测试集结果。论文附录表5另标 Accuracy，而主文称通篇 F1，因此不能将该附录数字无说明混进 F1 表。定性例还显示：错误反馈可能把 jailbreak 检测改成更窄的另一任务，或者产生标签语义翻转。应对新提示做任务定义与输出标签一致性检查。

### 可复现性与最小真实本地实验（建议，未执行）

可复现性：中等。算法与模板公开，但原版闭源 API、数据抽样和模型快照影响数值一致性。替换本地模型属于方法缩小复现，而非原成绩复现。

建议实验：用同一个固定的 3B–8B 指令模型分别承担分类、批评和改写，选择公开二分类数据；至少 64 条训练、32 条验证、100 条独立测试。做 3 轮，beam=2，每个父候选生成2条批评、每条1次改写，再加入等量释义候选。保留至少原提示、等预算随机释义、完整反馈搜索三个条件；分类温度固定，搜索随机种子至少3个。报告 F1、混淆矩阵、tokens、所有候选与选择日志。若只用人工写好的“梯度”或预先设定得分的假分类器，就只是机制演示。

## 2. TextGrad / Optimizing generative AI by backpropagating language model feedback

### 来源与阅读边界

- [arXiv v1 全文](https://arxiv.org/pdf/2406.07496v1)：2024-06-11，41 页，题名 TextGrad: Automatic “Differentiation” via Text。
- [Nature 正式记录](https://www.nature.com/articles/s41586-025-08661-4)：2025-03-19，Nature 639，609–616。
- [Nature 官方补充材料](https://media.springernature.com/original/springer-static/esm/art%3A10.1038%2Fs41586-025-08661-4/MediaObjects/41586_2025_8661_MOESM1_ESM.pdf)：42 个 PDF 页，含 Supplementary Notes 1–10 与最终版表格。
- [代码](https://github.com/zou-group/textgrad)，正式文章指定 [v0.1.6 归档](https://doi.org/10.5281/zenodo.14497017)。
- 已读预印本方法、实验、附录，核对正式版补充方法/表1–3及公开主图4。Nature 主文入口为订阅预览，因此不能声称已逐页读取付费正式主文；结论以可取得的全文和明确标注版本的材料为准。

### 核心方法与实测锚点

TextGrad 保存变量的值、角色、前驱与语言反馈，沿计算图反向分配批评，再由文本优化器改写变量。预印本表2（p.10）：GPT-4o 的 GPQA Diamond accuracy 从 CoT 51.0% 到55.0%；这是测试时答案修订，非权重训练。正式补充表1（印刷p.17 / PDF p.18）：GPT-3.5 的 GSM8K 为 CoT 72.9%、OPRO 76.8%、DSPy 81.1%、TextGrad 指令加3示例82.4%。正式主图4e：ScienceQA-IMG，Chameleon 77.5%，TextGrad 三次优化85.2%。[预印本](https://arxiv.org/pdf/2406.07496v1)；[正式补表](https://media.springernature.com/original/springer-static/esm/art%3A10.1038%2Fs41586-025-08661-4/MediaObjects/41586_2025_8661_MOESM1_ESM.pdf)；[正式图4](https://media.springernature.com/lw1200/springer-static/image/art%3A10.1038%2Fs41586-025-08661-4/MediaObjects/41586_2025_8661_Fig4_HTML.png)

### 分析：框架贡献和证据边界

它把以往逐例反思推广成可组合的计算图接口。关键是给上游变量“带有下游上下文的反馈”，不只是叫模型再回答一次。对最终答案的测试时优化与训练集上的提示优化是两种不同的评测协议：前者每题都要额外成本，后者是一次优化后复用。

注意四个边界：第一，强模型提供的反馈是重要资源，不能把优化后的弱模型分数归功于弱模型独立自我学习。第二，自评也可能产生错误反馈，必须单列“原来答对却改错”的比例。第三，分子 docking/QED 与五个放疗计划上的数值指标不能证明药效、临床安全或治疗获益。第四，更多推理调用与改进算法应分开比较，至少有同 tokens 的多次采样/投票基线。

版本核查：预印本表1（p.8）的代码完成率为 zero-shot 0.26、Reflexion 0.31±0.012、TextGrad 0.36±0.018，但相邻正文写 zero-shot 0.23；其“20%相对提高”也不宜用四舍五入表值机械重述。报告这些数据时标明内文不一致。正式补充材料把 BBH 切分记为51/100/99，预印本记为50/100/100；复现实验必须固定所依据的版本。

### 可复现性与最小真实本地实验（建议，未执行）

可复现性：提示优化较高、整个跨领域结果中等。完整数值复现需要指定 API 快照、示例/题目索引、验证回滚与最终选择规则；代码任务还依赖隐藏测试集。正式补表2采用70B开放权重模型作反馈器，不是“3B独立优化已证实”。正式补表3也有迁移退化，例如 Llama-3.1-8B 的排序分数46.5%→45.5%。

最小实验从 object counting 入手：按所选版本固定训练/验证/测试切分，使用本地固定 7B–8B 指令模型作 forward、critic、optimizer，batch=3，运行12次候选更新，每轮验证决定是否接受；保存每条答案、反馈、提示和回滚。用确定性的最终整数解析评分，防止“LLM评委替LLM打分”掩盖误差。除原始提示外，加入“直接改写、不反传上下文”和同预算随机提示两个基线。

若要真正验证计算图贡献，再加一个两节点流水线，并比较只改最终答案与同时更新两个上游变量。只实现单节点反思，可称 TextGrad 风格小规模实验，不能覆盖任意图自动反传的主张。1B–3B 也能用于真实探索，但失败不能证明框架普遍无效，成功也不能替代70B反馈器的原设定。

## 3. FedTextGrad / Can Textual Gradient Work in Federated Learning?

### 来源与版本

- [arXiv v1 全文](https://arxiv.org/pdf/2502.19980v1)，2025-02-27，22 页；论文页和首页均注明 ICLR 2025。
- [官方实现](https://github.com/ubc-tea/FedTextGrad)。已读正文§1–6与附录A–H，尤其异构、小模型迁移、动态聚合及surprisal分析。

### 核心方法与实测锚点

客户端用 TextGrad 更新本地提示；服务器收集提示，拼接、摘要或使用 UID 指引摘要，再广播。默认 Llama-3.1-8B、3客户端、batch=3、本地3步。§4.2（p.8）：多步算术的拼接/摘要 accuracy 为0.69/0.55。异构附录表4（p.21）：batch=3时摘要0.78(0.02)，UID摘要0.79(0.02)。表3（p.20）：11B优化提示迁移到3B，计数0.66→0.69，算术0.51→0.66，GSM8K 0.80→0.72。[原文](https://arxiv.org/pdf/2502.19980v1)

### 分析：真正难点是合并什么

上传的是优化后的提示，不是数学意义的梯度向量；“联邦平均”在这里没有自然的加权平均运算。拼接可能保留细节却膨胀上下文，摘要可能删除对少数客户端重要的条件，因此聚合质量是独立于本地优化质量的第二层问题。

UID 的小幅提升值得作为假说研究，但不宜写成已经证明信息密度是因果机制。附录H给出的平均/最大 surprisal 接近，不能直接证明完整保留客户端信息，更不能替代任务级反事实消融。要用相同长度预算比较摘要、UID摘要与随机同义改写，避免把“写得更长/更明确”误当成特定理论的证据。

隐私是明显边界：不上传原始数据不等于隐私安全。提示可能复制训练例或罕见属性，使用远端反馈器还可能直接把本地样本交给 API。论文将隐私和恶意客户端鲁棒性列为后续方向；没有差分隐私预算、隐私攻击成功率或真实端侧部署证据。复杂推理附表2（p.20）也显示集中式优于联邦式的多个任务，因此不能说联邦化通常优于集中优化。

### 可复现性与最小真实本地实验（建议，未执行）

可复现性：中等。官方仓库提供集中、同构、异构入口及本地服务说明，但必须追查确切划分、全局轮数、随机种子、括号误差定义及服务器选择机制，不能从图中猜精确值。

建议同一台机器模拟3个逻辑客户端，各有独立训练/验证数据，所有模型调用都走本地固定7B–8B端点；客户端不交换题目，只输出实际生成的提示。至少比较本地独立优化、集中 TextGrad、拼接、普通摘要、UID摘要；控制每客户端样本量、总优化调用和聚合长度预算。先做同任务随机划分，再按任务或输入复杂度做 non-IID 划分。记录全局和每客户端 accuracy、最差客户端分数、提示长度、通信字节和更新轨迹，至少3个种子。

这可以是真实的“小规模联邦提示优化方法实验”，但它仍是单机模拟，不能称真实跨设备联邦部署。用手写字符串替代模型的本地反馈、用人工摘要替代服务器模型，或者只演示把三个提示拼起来，均只属于流程演示。

## 4. SPRIG / Improving Large Language Model Performance by System Prompt Optimization

### 来源与版本

- [用户给定 OpenReview 记录](https://openreview.net/forum?id=VdVV24KSWK)，ICLR 2026 Poster。
- [ICLR 2026 正式全文](https://proceedings.iclr.cc/paper_files/paper/2026/file/2c9d78ed62ff5bf2377c3840188114c0-Paper-Conference.pdf)，24页；[arXiv v3](https://arxiv.org/pdf/2410.14826v3)为2026-04-04。v1/v2 是2024年旧稿，不能不标版本沿用旧结果。
- [论文指向的官方仓库](https://github.com/orange0629/prompting)。阅读覆盖方法、泛化、隐状态分析和附录全部实验设置；已目视核验附录表2。

### 核心方法与实测锚点

SPRIG用遗传编辑搜索跨任务系统提示，并训练 ModernBERT 奖励模型给候选排序；真实基准评分用于更新该代理。主模型为 Llama-3.1-8B、Mistral-Nemo-12B、Qwen2.5-7B，42个优化域任务与5个多语言外域基准。附录表2（p.18）的混合平均分：原提示0.5232、CoT 0.5972、SPRIG 0.6287、ProTeGi 0.6541、组合0.6714。组合相对ProTeGi的配对检验p=0.053。附录A.4（p.20）报告每模型约4张L40S 48GB、20小时优化。[正式全文](https://proceedings.iclr.cc/paper_files/paper/2026/file/2c9d78ed62ff5bf2377c3840188114c0-Paper-Conference.pdf)

### 分析：可复用系统提示不等于万能提示

研究设计最有启发的是把系统级与任务级指令分开，并验证先优化系统、再条件化优化任务的顺序。这里的平均分混合了accuracy、F1及开放问答评分，不能直接改称“总体准确率”。0.5232→0.6287的绝对增量是0.1055；它不是10.55%的相对增量。

组合的点估计最高，但p=0.053未跨过常用0.05门槛，不能宣称组合对task-only有明确统计显著提升。§5还说明跨模型收益会缩小；单独system/task提示迁移到更大模型的效果不显著。论文的泛化结论应理解为有限任务/模型集合上的证据，不是任意模型的无条件可迁移性。

PCA图可以说明不同提示对应不同隐藏状态分布，却不能单凭二维投影证明“系统提示移动到全局高性能区域，任务提示在局部优化”的因果机制。组件库、候选长度、评价任务及奖励模型可能共同决定结果。对安全、角色、情绪等提示还需另做行为与偏见测试，不能只优化一个平均分。

### 可复现性与最小真实本地实验（建议，未执行）

可复现性：资料较充足，资源门槛高。完整版不只是套遗传算法：它有9000组件、10000已评分提示、100000偏好对、奖励模型和25轮搜索。照原规模跑，不能称“轻量本地实验”。

最小迁移实验：无需重跑搜索，固定本地7B–8B模型，对同一套未见测试题比较空系统提示、CoT和作者公布的系统提示，并按至少4种任务分别报告差异。这验证提示转移，不验证SPRIG优化器。

最小优化器实验：用50–100个合法组件、种群20–50、5轮、3–4任务，每任务保留独立测试；真实小模型生成并评分，加入等预算随机搜索，保持相同提示长度预算。如果省略奖励模型而全部实测，应明确称“SPRIG遗传搜索简化变体”。若称缩小的完整SPRIG，至少要训练/更新一个真实的成对排序模型，并在未见候选上报告Spearman/NDCG，证明它比随机排序有用。只排列人工打分的模板属于机制演示。

## 5. MASS / Multi-Agent Design: Optimizing Agents with Better Prompts and Topologies

### 来源与版本

- [arXiv v2 全文](https://arxiv.org/pdf/2502.02533v2)，2026-01-31，ICLR 2026；v1为2025-02-04。
- 已读§2设计空间、§3算法、§4实验、附录限制、数据划分、成本、模型/优化器消融和提示模板；已目视核验主表1。
- 此次没有确认到论文作者维护的官方MASS实现入口。不能把同名第三方项目冒充论文代码；算法1与附录模板可用于独立实现。

### 核心方法与实测锚点

三阶段为局部提示优化、拓扑搜索、全系统提示再优化；实现使用MIPRO联合搜索指令与示例。主表1（p.8）：Gemini-1.5-Pro的8任务混合平均分，MASS 78.79、Debate 70.26、ADAS 69.72；MATH accuracy为84.67±0.47。Flash 的MASS平均74.30。开放权重补表5（p.21）：Mistral-Nemo-12B四任务平均55.9，CoT40.4、Debate46.9。主结果三次评估，测试集为原基准的抽样子集。[原文](https://arxiv.org/pdf/2502.02533v2)

### 分析：先修代理，再决定怎么组队

设计贡献是承认弱提示会在串联中放大错误，因此先把单个模块做好，再搜索如何组装，最后修复模块间的交互。它不是任意代理图的无限搜索：存在预定义模块和编排顺序，拓扑搜索范围与预算很大程度决定最终结果。

平均分混合accuracy、F1和pass@1，必须保留指标名称与任务数。LiveCodeBench在这里是“测试输出预测”，不能冒称通用代码生成成绩。AFlow*还使用不同优化器模型，部分任务超时，所以该行不能解释成完全受控的所有方法排名。Flash的MuSiQue中MASS也低于ADAS，不能写“各任务全面最优”。

成本应同时算离线搜索和在线推理。表7（p.22）在其当时定价下列MASS搜索24M输入+11M输出tokens；这些是历史实验成本，不能用于今天的购买报价。相同代理数量并不代表相同tokens，建议重做严格token匹配。另有排版/统计一致性问题：附表6的最终逐任务分数与主表1相同，但其平均列写78.40，主表为78.79；根据该行八个数重算约78.79，应注明差异，不复制错误平均。

### 可复现性与最小真实本地实验（建议，未执行）

可复现性：中等偏低。详细算法和模板有助独立实现，但本次未确认官方代码，加上闭源主模型与小测试子集，原始成绩复核仍有限。

建议一个固定7B–12B本地模型顺序模拟多角色，无需每代理各占一份GPU权重。选择可用确定性评分的算术或短上下文问答；训练/验证/测试分离，优化单模型提示，再在单代理、3采样聚合、生成-批评-修订这3类拓扑中搜索，最后对最佳拓扑重做联合提示优化。至少做“只优化提示”“只优化拓扑”“完整三阶段”消融，锁定总候选/推理token预算，报告每阶段测试分数、tokens及延迟。若没有真实模型生成的模块输出和真实验证筛选，仅用固定字符串模拟多代理交互，就不构成MASS实验。删去阶段或用手工挑拓扑，要明确叫MASS-inspired。

## 6. 官方实践：用 Codex 构建可自我改进的税务智能体（非论文）

### 来源与可核查内容

[OpenAI 官方工程文章](https://openai.com/zh-Hans-CN/index/building-self-improving-tax-agents-with-codex/)，2026-05-27，作者包括Thrive Holdings与OpenAI团队。全文已读；文章不含论文式实验协议、随机化对照或可下载生产数据。

系统将专家字段修正、带来源的生产追踪与定向/回归评测连接，再由Codex提出候选修复PR，工程师负责上线、从业者审批申报。文章报告试点处理7000份申报、准备时间约减三分之一、吞吐量约增50%；达到75%正确字段完成率的申报占比六周从约25%升至86%。租赁场景达到90% precision/recall约需六周且有大量工程监督。[官方原文](https://openai.com/zh-Hans-CN/index/building-self-improving-tax-agents-with-codex/)

### 分析与可迁移的工程要求

这里的“自我改进”是评测驱动的软件迭代闭环。文章没有证明模型自己在后台持续更新权重，也没有证明无人监管报税。其“高达97%准确率”、字段完成阈值、特定场景precision/recall是不同口径，不能拼成统一成功率。客户/文档难度会随时间变化，且缺少对照、置信区间和完整评分定义，改善幅度应标为作者报告而非可独立复核的因果收益。

最值得迁移的是先固定证据链：源材料→提取字段及引用→映射结果→专家修改→修复评测→回归门禁。修复评分器也可能让分数表面变好，所以评分规则变更必须单独审计，测试证据应只读。

最小本地实验（建议，未执行）：用完全合成的发票/租赁字段材料，设计一类真实提取错误；本地小模型真实提取，人工提供一次明确修正，再把它变成锁定测试，尝试有范围的提示/映射规则修改，并在未见合成样本上回归。保存before/after、字段级precision/recall、来源定位与错误案例。它能验证工作流，不能复现真实税务产品97%的表现，更不应连接真实报税账号或使用私人税务数据。

## 统一实验门槛与优先级

以下为我们提出的研究计划，不是论文已证实的硬件承诺。

1. 最先做 TextGrad/ProTeGi 的单模型提示优化：任务小、评分可确定，最容易区分真实改进和文字表演。
2. 再做 FedTextGrad 的同机多客户端模拟：增加的核心变量是数据分布和聚合方法。
3. MASS 在单模型基础上增加三类流程及阶段消融，避免先堆十几个代理。
4. SPRIG先验证现成系统提示迁移，再决定是否承担奖励模型与搜索预算。
5. Tax AI仅复现合成数据下的证据、修正、回归闭环，不用真实性能数字包装演示。

共同最低记录：模型完整标识/权重哈希、量化与推理后端版本、提示模板、数据索引和哈希、随机种子、原始输出、候选接受/拒绝、调用次数、输入输出tokens、总时长、峰值内存、锁定测试分数及失败例。至少3个种子或配对bootstrap置信区间；小样本点估计可以报告，但不必强行宣称显著。

资源估算：7B权重仅4-bit理论存储约3.5GB，FP16约14GB；运行还需KV cache、临时张量和框架开销，不能把权重大小当成显存需求。以短上下文单并发量化推理设计，12–16GB级显存更有余量，具体必须实际测量。3B可以降低门槛，但批评/改写能力可能成为瓶颈。完全本地实验应同时让forward与feedback本地运行，不能暗中调用大模型API再标“小模型独立自改进”。

“可运行骨架”只证明代码路径能跑；“机制演示”证明流程可观察；“小规模方法实验”要求真实模型、独立测试和对照；“论文复现”还要求与原文模型、数据、预算和统计协议可比。报告应始终写清属于哪一层。
